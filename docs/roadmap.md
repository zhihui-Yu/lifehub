### 3.3 分工原则

1. **红线双签**：`X-01`、`X-05`、`X-06`、`X-15` 的实现由 ARCH 负责技术落实、QA 负责核验、PM 负责合规判定，**三方任一否决即阻断发布**。
2. **核心层单一归属**：`packages/core` 的领域逻辑与接口由 ARCH 定义与评审，实现由 FE/BE/MOB 协作，但**签名变更必须走 ARCH**（防止 Web 与 Flutter 端漂移）。
3. **接口先于实现**：`CryptoProvider` / `StorageAdapter` 两个端口在 S1 冻结，S3/S5 不再改签名；若必须改，走 ADR + 迁移函数 + 兼容窗口 ≥ 1 个大版本（NF-M-7）。
4. **测试左移**：夹具与用例由 QA 与实现者**同批产出**，不等到阶段末尾补测。

### 8.5 下一阶段的三个前置提醒

1. **同步协议（S5）必须补上「删除墓碑」**：本期合并算法没有「删除 vs 修改」的语义，
